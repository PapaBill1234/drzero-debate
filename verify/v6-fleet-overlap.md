## D26: overlap phases of one gate

The serial order is real (`gate_fast.sh:65-67`). Three of the four sub-items fall away. (1) Funcdiff per exe in parallel is done: the wine shim prefetches the funcdiff after each link. Only the last exe often runs serially, and that costs about 9 s per build. (2) "Start parity.sh when the clang build ends" overlaps only the gate_extra tail (median 40.6 s, p90 106 s). D21 does exactly this with `GATE_EXTRA=defer` and adds a cache, so the two gains do not add. (3) `--first <exes>` needs a bns-lift `parity.sh` change. It skips the off-target MATCH -> DIFF signal in failed rounds. Its gain (1-4 min ❓) comes mostly from local contention, and D28 removes that contention. What is left is the clang/VS2010 compile overlap (the run2-08 prep-plus-2-branches design). The clang part is only a median 25 s, and the host is CPU-bound and disk-bound. Measure it again after D19-D21 and D28.

## D27: fresh_build calls buildonce gate

The gap exists, but it has no cost. In the v2b wave, no cardrun full_build tree repeated, and no tree matched an author `buildonce gate` entry. The author lane mostly built ref/noref, and the rev changed after rebase. The repeats are base builds of docs-only mains. The base lock already shares those builds per main, and D22/D23 remove them. A key without `Docs/` is wrong for a gate result, because `gate.rc` includes the baseline compare. A remote store path is not needed while D28 pulls the outputs back.

## D28: full_build and base_build through slotq

The defect is confirmed. cardrun never calls slotq, and the `build_direct` mode is dead code. The remote hosts were not "down": `build2.down` (01:26:32) and `build3.down` (01:26:08) expired after 600 s (`slotq.py:731-737`). Author builds went remote only twice, at 14:40, because `slotq run` goes remote only while a job waits for a local slot. Local links under load took a median of 27.9 s (max 118.7 s). Remote links took 4.7-9.0 s. A remote run with a cold vsobj store took 136-149 s; local full_build had a median of 246 s. Remote output decides MATCH credit (`build_ok`, lost_check, strict and proof read the pulled files), so ship this only with D05 and one byte audit per host. Wrap the command at run time. This keeps COMMANDS and the base-cache digest the same. Use the existing `SLOTRUN_PRIO=land` refusal for land-mode rechecks. Remote pulls carry no `obj/`. This is fine for the steps (`remote_build.py:357-358`), but it makes D29 pull necessary. The cardrun slot stays held during the remote run (by design). The gain is local CPU and disk, not more parallel cards.

## D29: warm remote namespace

The objsync hook works, but it is off. A hosts.json edit turns it on. Without D28 the gain is 0 s, because no card build goes remote. With D28, each cold remote card build saves about 120 s (measured on idle hosts). "Force a push per namespace" is what the push hook does: it sends only the missing entries. Do not sort hosts by warmth yet: with push on, every host is warm. Reject the EXIT_INPUT change for a missing `gate.rc` (`remote_build.py:427,471`). The only exits before `gate.rc` (`gate_fast.sh:22,37,41,42`) are host faults: uv site, wine dir, prefix id and disk_guard. A host cool-down is right for them. EXIT_INPUT would stop all remote tries for that job and leave the broken host in rotation. The g17 rc-3 cause was fixed in e878667f (02:07). "Why did dispatch stop": see D28.

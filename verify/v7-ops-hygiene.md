## Reasons

**D31 = O1 (LATER).** The defect is real. Every gate in the list still calls the global quota.check(), and the record has no scope. But a pause never fired in this engine: there is no /data/parity-v2/PAUSE and no PAUSE.log. The 80 card-days figure is a guess. It assumes a weekly limit, a model-free lander that keeps running, and 10 READY cards that wait. Today a Claude lead and operator drive the lands, and the same limit can stop them too. leases.py already stops only the affected model for pilot calls. Build it when the D32 lead driver makes lands model-free, or after the first real pause.

**D34 (BUILD-SMALL: parts C and D only).** Torn JSON: 0 of 909 files. Lock errors: 0 of 31,415 files. The repair.py race is not reachable, because only one operator holds the flock and running.json is now atomic. So the bulk switch and dbx.py/WAL are hardening with no measured harm. Two parts are cheap and fix real gaps. (C) sync.sh copies live ledgers raw; a hot journal on disk shows that writers do die mid-transaction. (D) score.py:101 turns any lock error into "no excluded symbols", which can make a MATCH report count excluded symbols. Agent A owns sync.sh through D33, so part C must land after D33.

**D35 (BUILD-SMALL: guard stderr only).** The shared gitx.py saves about 1,100 tokens of copies. The data shows 1 harmless lock event. Do it later. The stderr loss is real but has moved. check_before_push in guard.py now swallows CalledProcessError, so a fix at landq or cardrun cannot recover the text. The cardrun public_guard path (check_public) still raises, so cardrun.py:1586 can add the tail now with no digest cost. The guard.py fix needs a checker digest bump, so put it in the D04 change.

The cheap value is a guard test that stops new code-folder writers, plus the triage.py default. The other default writers are checker files (buildonce.py, linked_build_main.sh, linked_build_noref.sh). Move them only inside D04.

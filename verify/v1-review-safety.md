## Reasons

**D06 (P4-P9 rules).** The gap is real. `precheck()` has only P1-P3 (`review.py:259-262`). P3 ignores a zero immediate on purpose (`review.py:22`), so the r9 case passes. I re-ran the replay. 8 of 12 rejected items with a bundle get a hit. But the hits on accept draws (19) come from P6 and P8. They fall on Appearance/Race/SexOk (G01/G03/G05). These are frozen "good" items in `review_regress.json`. fix10 showed that the moved load crosses a pure leaf GetId call. P6 also flags SCD wmain, which was credited: the prologue spills through `rax`, and the filter does not see that. The proposal calls these items "defect items with accepts". That is wrong. P4, P5 and P9 alone catch 5 of 12 rejected items (find, PresenceKick, ClientSessionTimerJob, execute, wmain). They flag 0 of 33 accept-only bundles. Ship only these 3 rules. The integrate recheck is already done: integrate needs the current review digest, and a precheck edit must bump it. The 2-draw rule uses stale data. All measured flips are before fix10. Since fix10 there are 0 flips. The token gain (about 90 draws) also uses old repeated draws. The model now rejects K2 and K6 on its own. The real value is robustness, and a cheaper model later. Bump the review version only once, together with the D02 re-review.

**D07 (R9 safety_guard).** The gap is real. G1/G3 run only in the pilot loop. Auto credit needs strict full+cfg (`proof.py:189-191`), but the G1/G3 class is invisible exactly there (LTCG). Auto credit is 18 of 51 (35 %), not 2/3. Coverage is weak today: 0 true hits, and the hit rate on landed cards is not re-measured ❓. So build R9 small, with the arity and same-key filter. A hit gives only no_auto, so the risk is low. The cost claim for the digest split is half wrong. The review re-draw already carries by bundle digest at 0 tokens. Only full_build (about 287 s per card) runs again. Leave the split to the D04 owner. D04 rewrites the same CHECKERS and keys. The D23 conflict is small: D23 re-plans on safe paths. R9 diffs base against candidate, so it stays valid.

**D08 (model canary).** Part of it exists. The frozen set and one live run (fix10, 3 runs, 0 flips) are there. The runner is outside the repo and has no trigger. The proposal's 84 mutants put D lines in the bundle with no matching C/J/I lines, and the judge found a fault in the overload mutant. Real items are a better test. Put the gate in `test_review` next to BEHAVIOUR_PIN. Do not put it in `integrate.py`, because integrate never sees a model or prompt change. Build it before any review cut (smaller model, trimmed bundle).

**Q9 (stub first lifts).** No, not with today's rules. G1/G3 compare the old body with the new body. A stub has unnamed parameters and no calls, so both rules give []. This matters now: 313 stubs remain, all of them in LobbyDaemon, the next target. A small G1 variant works: when the old body is a stub, a parameter that is unnamed or unused in the new body gives no_auto. The measured false-positive base rate is 7.9 % of definitions. That sends some items to a review draw (about 3-7k tokens each). G3 has no reference for first lifts. Only the review (with the callee source) can see a dropped inlined guard there. Add one fixture: a stub-to-lift card that replaces a parameter with a constant. It must give `review`.
